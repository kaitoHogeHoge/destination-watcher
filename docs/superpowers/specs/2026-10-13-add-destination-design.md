# 行き先の追加・削除ボタン 設計書

作成日：2026-10-13
元の設計書：`2026-10-13-destination-watcher-design.md`（この設計書はその追加分）

## 1. 目的

`config/destinations.json` を手で編集しなくても、GitHub の Actions ページで都市名を入力するだけで行き先を追加・削除できるようにする。スマホのブラウザからも操作できること。

### 成功の条件

- Actions ページの「行き先を追加」に「バンコク」と入れて実行すると、数分後に公開ページへバンコク（タイ）のカードが増える
- 実行結果の画面に、追加した都市・国と、対象外になる情報が日本語で表示される
- 「行き先を削除」に画面上の都市名を入れて実行すると、設定と保存データの両方から消え、公開ページからカードが消える
- 見つからない・登録済み・削除対象が無いときは、何も変えずに理由を表示して終わる
- 費用0円・サーバーなしのまま

## 2. 使い方

### 追加
1. Actions ページ →「行き先を追加」→「Run workflow」
2. 「都市名」（必須）を入力する。同名の都市が他国にありそうなときは「国名」（任意）も入れる
3. 実行結果に「バンコク（タイ）を追加しました」「対象外の情報：祝日」などが出る
4. 続けて「データ更新」が自動で動き、取得と公開が行われる

### 削除
1. Actions ページ →「行き先を削除」→「Run workflow」
2. 画面に出ている都市名（例：バンコク）を入力する
3. 設定と `site/data/{id}/` が消え、「データ更新」が自動で動いて公開ページに反映される

## 3. 都市から設定を作る

### 3.1 地名検索

- API：Open-Meteo Geocoding `https://geocoding-api.open-meteo.com/v1/search`
- params：`name={都市名}`, `count=10`, `language=ja`
- 結果の選び方：
  - 国名が入力されていれば、結果の `country`（日本語）に入力が含まれる、または入力に `country` が含まれる最初のもの
  - 国名が無ければ最初のもの（API が関連度・人口の順に返す）
  - 該当なし → 「『{都市名}』が見つかりませんでした。英語名（例：Reykjavik）でも試してください」
- 日本語の表記ゆれに弱い（例：「レイキャビク」は見つからない）。英語名なら見つかる

### 3.2 設定の1件分

| 項目 | 値 |
|---|---|
| `id` | `{国コード小文字}-{検索結果の id}`（例：`th-1609350`）。英数字と `-` だけ |
| `name` | 検索結果の `name`（日本語） |
| `country` | 検索結果の `country`（日本語） |
| `country_code` | 検索結果の `country_code` |
| `mofa_code` | 国の対応表から（無ければ `null`） |
| `lat` / `lon` | 検索結果の値を小数2桁に丸める |
| `currency` | 国の対応表から（無ければ `null`） |

`holiday_region` は自動では付けない（必要なら手で足す）。

### 3.3 国の対応表 `config/countries.json`

```json
{ "TH": { "currency": "THB", "mofa_code": "0066" }, ... }
```

- 作り方：`scripts/build_countries.py` を一度実行して作り、リポジトリに入れる（毎回の実行では外部に問い合わせない）
- 元データ：
  - 国と通貨・国際電話番号：mledoze/countries 5.1.0 の `countries.json`（ODbL-1.0。README に出典を書く）
  - 外務省の国番号：外務省 海外安全情報オープンデータの国コード一覧（`country.xlsx`）
- `currency`：その国の最初の通貨コード。無ければ `null`
- `mofa_code`：国際電話番号（`root` + `suffixes` が1つのときはそれを連結、数字だけを4桁に0埋め）が外務省の一覧にあればそれ。無ければ `null`
  - 例外（手で決める）：米国 `US` → `1000`（本土）、カナダ `CA` → `9001`
- 元の国の対応表を作り直したいときは、スクリプトを実行し直す

### 3.4 重複の確認

次のどちらかに当たる行き先がすでにあれば「すでに登録されています：{name}（{country}）」として何も変えない。
- 同じ `id`
- 同じ `name` かつ同じ `country`

## 4. 削除

- 入力した文字が `name` または `id` と完全に一致する行き先を探す
- 0件 → 「『{入力}』は登録されていません。登録中：ロンドン、トロムソ、…」
- 2件以上 → 「同じ名前の行き先が複数あります。id で指定してください：…」
- 1件 → 設定から消し、`site/data/{id}/` を削除する

## 5. 対象外の扱いの追加

- `mofa_code` が `null` の行き先は、安全情報を `unsupported` にする（`SafetySource.supports`）
- `currency` が `null` の行き先は、為替を `unsupported` にする（`ExchangeSource.supports`）
- 設定ファイルの読み込みでは、`mofa_code`・`currency` に `null` を許す。ただし値があるときは文字列でなければ飛ばす（`country_code` も文字列必須）。前回後回しにした「型のチェック」もここで行う

## 6. 自動実行（GitHub Actions）

### 6.1 `add-destination.yml`

- `on: workflow_dispatch`、入力 `city`（都市名・必須）、`country`（国名・任意）
- 入力は **必ず環境変数経由** で Python に渡す（`run:` の中に `${{ inputs.city }}` を直接書かない。入力に記号を混ぜてコマンドを実行させる攻撃を防ぐため）
- 手順：checkout → Python 準備 → `python -m fetcher.add` → 設定の変更をコミットして push（`git pull --rebase` してから）→ `gh workflow run update.yml` で「データ更新」を呼ぶ
- GITHUB_TOKEN による push では他の自動実行が起動しないため、「データ更新」は明示的に呼び出す
- 権限：`contents: write`、`actions: write`
- 結果の文章は `$GITHUB_STEP_SUMMARY` に書き、実行結果の画面に出す
- 失敗（見つからない・登録済み）のときは何もコミットせず、終了コード1で終わる（❌ と理由が出る）

### 6.2 `remove-destination.yml`

- 入力 `name`（都市名または id・必須）
- 手順は追加と同じで、`python -m fetcher.remove` を使う。コミット対象は設定と `site/data`

### 6.3 同時実行

追加・削除・データ更新は同じ `concurrency` グループ（`update`）に入れ、同時に動かない。

## 7. テスト

- 地名検索の結果の選び方（国名あり・なし・該当なし）
- 設定の1件分の作り方（対応表にある国・無い国）
- 追加（追記されること、重複の検出、日本語がそのまま書かれること）
- 削除（名前・id で消える、データのフォルダも消える、見つからない・複数）
- 対応表の作り方（電話番号から国番号、例外、外務省一覧に無いとき `null`）
- 対象外の判定（`mofa_code`・`currency` が `null`）
- 設定の型チェック
- 実際の自動実行は、公開後にバンコクを追加 → 表示を確認 → 削除、で確かめる

## 8. やらないこと

- 公開ページ上の入力欄（誰でも追加できてしまうため）
- 候補が複数あるときに選ばせる画面（国名の入力で絞る）
- 日本語の表記ゆれの吸収
